## 切歌方法

代码是 [tools/split_songs.py](../split_songs.py)，在 AutoDL 上对应 `songsplit` 任务。

1. 用 PANNs（Cnn14_DecisionLevelMax，在 AudioSet 上预训练）逐秒判断唱歌、说话和音乐的概率。唱歌时说话概率接近 0，唱歌概率明显大于 0；聊天时说话概率在 0.27～0.55。直播聊天时一直开着 BGM，所以音乐概率不能用来区分唱歌和聊天。
2. 唱歌概率大于 0.02、同时说话概率小于 0.1 的秒算作唱歌。间隙不超过 45 秒、其中说话少于 15 秒的（间奏、即兴喊话）连成同一首。前后有伴奏、没人说话的部分作为前奏和尾奏保留，最多 30 秒。短于 60 秒的丢掉。
3. 歌名：评论里粉丝发的道标（歌单时间轴）按时间对应到歌上；时间打错的按歌单顺序对应。15 分钟以内的单曲视频用视频标题里的歌名。没有道标的录像里，歌名记为“未知”。
4. 逐秒概率会缓存下来，改参数重新切不需要再跑模型。

### 参数调优

用 6 场有道标的录像（共 61 首）作为标准答案扫描参数：

| | 初始参数 | 调优后 |
|---|---|---|
| 找到的道标歌曲 | 61 / 61 | 61 / 61 |
| 有道标的录像里多出的片段 | 18 | 3（都是 3～4.5 分钟的完整演唱，道标里漏记了） |
| 两首被并成一段 | 0 | 0 |
| 14 场录像的总片段数 | 224 | 177 |

初始参数会把间奏里说了几句话的歌切成两段，也会留下 46 秒左右的碎片。

速度：无卡模式的 CPU（0.5 核）约为实时的 5 倍；RTX 4090 D 上 33 小时录像约 4 分钟处理完。

## 本轮修复的问题

- 无卡模式只有 2GB 内存，下载 UVR 模型时加载 900MB 权重被系统杀掉。改为只下载、不加载。
- 无卡模式的 `nvidia-smi` 不列出 GPU 却返回 0，让 GPU 检查失效。改为检查是否真的列出了 GPU。
- 通过 SSH 启动 runner 时 PATH 里没有 `python3`，试听网页没有启动。改用 conda 自带的 python。
- 试听网页的请求日志会记下访问密钥，而这份日志会推到公开的 `autodl-logs` 分支。现在日志里记成 `key=***`。
- GitHub token 失效，日志推不上去。已在 2026-10-17 更换。

## AutoDL 使用备注

- 无卡模式：0.5 核 CPU、2GB 内存、没有 GPU，¥0.10/时。适合下载、用缓存重新切歌、试听。
- 有卡模式（RTX 4090 D）：¥1.88/时。人声分离和训练需要它。
- 无卡模式开机只能在网页控制台操作。官方 API 只支持 Pro 实例，而且只能有卡开机。
- 从 AutoDL 访问 GitHub、HuggingFace、zenodo 要走学术加速。B 站直连更快，但列出空间视频必须带登录 cookies，否则会被风控拦截（412 / -352）。
